# Лекторий — семантический поиск по видеолекциям

Русскоязычное веб-приложение для загрузки MP4/WebM и видео по ссылкам с платформ, поддерживаемых yt-dlp. Лекторий извлекает аудио, распознаёт русскую речь локальной моделью GigaAM-v3 через `stt-ru`, строит мультиязычный семантический индекс, показывает совпадения с таймкодами, синхронный транскрипт, краткий пересказ и тематические главы.

## Автономная демонстрация

Автономный комплект для показа поставляется отдельно от исходного кода этого репозитория, поскольку включает готовое видео и архив. Рабочая версия с загрузкой, обработкой речи и входом доступна на [demoground.ru](https://demoground.ru).

## Возможности

- загрузка MP4 и WebM (до 500 МБ) или импорт по ссылкам поддерживаемых yt-dlp видеоплатформ, включая YouTube, VK Видео и Rutube;
- выбор максимального разрешения при импорте по ссылке; загрузчик выбирает лучший доступный формат не выше выбранного и объединяет дорожки при необходимости;
- сворачиваемая боковая панель с запоминанием состояния;
- адаптивный интерфейс для телефонов: навигация над содержимым, компактный поиск и окна лекций без горизонтальной прокрутки;
- автоматическое обновление библиотеки после загрузки и при входе с другого устройства; одинаковые названия лекций получают суффиксы `(2)`, `(3)` и далее;
- локальный плеер Plyr для обработанных видео;
- аудиодорожка извлекается через FFmpeg;
- транскрибация `stt-ru` и GigaAM-v3 с пунктуацией и таймкодами сегментов;
- семантический поиск по нескольким лекциям на `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (FastEmbed/ONNX);
- встроенный плеер, переход к таймкоду и синхронная подсветка текущего фрагмента;
- краткий пересказ по содержанию речи, тематические главы и ключевые термины;
- повторная обработка сохранённого видео, включая ранее готовые лекции, с новым распознаванием и пересказом;
- отдельная учётная запись и собственная библиотека для каждого пользователя;
- очередь задач с этапами и процентом обработки, примерным временем, прогрессом передачи файла и скачивания по ссылке;
- видео шифруются AES-GCM, а названия, источники, конспекты, транскрипты и векторы шифруются перед записью в SQLite;
- пароли хранятся в виде стойких хешей, вход работает через защищённую cookie-сессию;
- временные расшифрованные файлы удаляются после обработки или перед запуском приложения;
- резюме и поиск выполняются локально: транскрипты не отправляются во внешнюю LLM.

## Запуск на VPS через Docker Compose

Нужен Docker Engine с плагином Compose, FFmpeg внутри контейнера устанавливается автоматически. GigaAM-v3 и мультиязычная модель эмбеддингов работают на VPS с 1 ГБ RAM и swap, но обработка идёт медленно на одном ядре. От 4 ГБ RAM заметно комфортнее. Первая обработка скачает модели. `ASR_MODEL` по умолчанию равен `gigaam-v3-e2e-rnnt`; кэш модели хранится в `DATA_DIR/hf_cache`. Для yt-dlp можно задать HTTP/SOCKS5 прокси через `YTDLP_PROXY`; прокси применяется только к ссылкам YouTube.

1. Создайте `.env` из `.env.example`. `APP_USER` и `APP_PASSWORD` создают первый кабинет при первом запуске.
2. Запустите `docker compose up -d --build`.
3. Откройте `http://<IP-сервера>:8000` и войдите с логином и паролем из `.env`.
4. Первую лекцию загрузите небольшого размера: скачивание моделей выполняется при первой обработке.

Зашифрованные данные хранятся в `./data` и `./uploads`. Файл ключа (`data/storage.key` в Docker или `/etc/lectorium/storage.key` при systemd) нужен для расшифровки. Смена модели влияет на новые лекции, прежние векторы уже записаны в базе.

Для постоянного публичного адреса рекомендуется поставить перед приложением Caddy или Nginx с HTTPS и проксировать трафик на порт 8000. Порт приложения можно оставить доступным только для прокси, задав `APP_PORT=127.0.0.1:8000`; тогда в `compose.yaml` строку публикации порта нужно использовать как есть, а значение `APP_PORT` задать `127.0.0.1:8000`.

## Запуск на Ubuntu через systemd

Установите `python3-venv` и `ffmpeg`, создайте пользователя `lectorium`, скопируйте проект в `/opt/lectorium`, создайте виртуальное окружение и установите `requirements.txt`. Подготовьте `/var/lib/lectorium/data` и `/var/lib/lectorium/uploads` с владельцем `lectorium`. Скопируйте `deploy/lectorium.service` в `/etc/systemd/system/lectorium.service`; создайте `/etc/lectorium.env` с `APP_USER`, `APP_PASSWORD` и при необходимости `YTDLP_PROXY`, задайте права `600`, затем включите службу через `systemctl enable --now lectorium`. Схему HTTPS обратного прокси для своего домена добавьте в Nginx или Caddy.

## Локальный запуск без Docker

Установите Python 3.11+, FFmpeg с `ffprobe`, зависимости из `requirements.txt`, задайте `APP_USER` и `APP_PASSWORD`, затем запустите:

```sh
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## API

- `GET /api/health` — проверка доступности;
- `GET /api/lectures` — библиотека лекций;
- `POST /api/lectures/upload` — multipart-загрузка файла и названия;
- `POST /api/lectures/link` — JSON `{ "url": "https://…", "title": "…" }`;
- `GET /api/search?q=…` — семантический поиск;
- `GET /api/lectures/{id}` — статус, конспект и главы;
- `GET /api/lectures/{id}/segments` — транскрипт с таймкодами;
- `DELETE /api/lectures/{id}` — удалить лекцию и её видео.

Краткий пересказ строится из опорных предложений по всей лекции. Названия глав формируются локальной языковой моделью, если заданы `SUMMARY_BINARY` и `SUMMARY_MODEL_FILE`, и принимаются только при совпадении с текстом соответствующего фрагмента; без неё используются заголовки по транскрипту. На развёрнутом экземпляре установлены `llama.cpp` и Qwen2.5-0.5B-Instruct.

## Развёрнутый экземпляр

Прототип развёрнут на [https://demoground.ru](https://demoground.ru). На сервере служба `lectorium.service` запускает приложение из `/opt/lectorium`; база и файлы хранятся в `/var/lib/lectorium/`.

В развёрнутой версии пользователи входят в отдельные кабинеты; каждая библиотека фильтруется по владельцу. Первичный кабинет создаётся из `APP_USER`/`APP_PASSWORD` в `/etc/lectorium.env`; последующие пользователи могут зарегистрироваться самостоятельно.

Для ссылок VK Видео и Rutube используется актуальный `yt-dlp`; поддержка публичных видео зависит от доступности конкретного ролика и настроек приватности. Список поддерживаемых источников ведёт проект yt-dlp: https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md.

## Соцсети и прокси YouTube

В панели администратора откройте **Настройки**. Параметры OAuth и прокси сохраняются в базе с шифрованием приложения.

Для OAuth создайте приложения у провайдера и укажите callback-адреса:

- Яндекс: `https://demoground.ru/api/oauth/yandex/callback`
- GitHub: `https://demoground.ru/api/oauth/github/callback`
- Mail.ru: `https://demoground.ru/api/oauth/mailru/callback`

Вход через соцсеть доступен для аккаунтов, с которыми провайдер уже связан. Новая привязка из личного кабинета не предлагается.

Восстановление через электронную почту отключено. Пользователь меняет пароль в личном кабинете; администратор может задать новый пароль при утрате доступа.

Для YouTube укажите адрес HTTP- или SOCKS5-прокси и нажмите **Проверить прокси**. Если адрес в настройках пуст, приложение использует `YTDLP_PROXY` из окружения. Прокси применяется только к ссылкам YouTube.
